CODE WRITTEN
- API layer, concurrency-limited fetching, TTL caching.
- Battle-log parser, validated against live replays across many formats.
- Statistics aggregation.
- Start page: six format buttons, top-100 ladder, recent top-100 replays linking
  out to Showdown, player search with real "user not found" validation.
- Player page: format scoping, game-count control, progress UI, four headline
  tiles, and the widgets — Most Used Team (whole teams), Most Common Wins,
  Most Common Losses, repeat rivals, Most Used Tera, Win Rate by Game Length,
  Ladder Rank Over Time, and the Replay Showcase.
- Ladder Rank Over Time is hand-rolled SVG rather than a charting library:
  Recharts would have roughly doubled a 100 kB bundle for one chart. Cost 1.8 kB.
- Trapinch theme in a single removable CSS file, plus Pokémon type icons.
- Team filter (2026-08-12): a radio on each "Most Used Team" row re-scopes the
  whole page to that team's games. Implemented as a re-count of replays already
  downloaded, so it costs no network and returns instantly; the team-identity
  rule is exported from one place so the filter and the tally can never disagree.
- Ladder replay counts (2026-08-15): each Top 100 row shows how many public
  replays that player has in the selected format, so a dead end can be skipped
  without opening it. There is no bulk endpoint - it is one request per player -
  so counts load only for rows scrolled into view, and they share the requests
  the Recent Replays list was already making and discarding. Fetching all 100 up
  front was rejected: it would have taken the start page from 21 requests per
  format view to 101, on an API we don't own.
- Remembered sample controls (2026-08-15): the game count and the unrated toggle
  persist across dashboards in localStorage, validated on the way back in so a
  stale stored count can't drive a fetch no button is showing. The game-count
  picker also appears a second time directly above Most Used Team, both copies
  driving the same state.

BUGS FOUND AND FIXED
Earlier sessions:
- Parser silently mishandled four-player Free-For-All battles.
- User lookup treated every typo as a valid account.
- Player page blended formats, showing Terastallization stats for a format that
  has none.
- Showdown's pagination returns duplicate replays, double-counting statistics.

2026-08-09/10:
- "50 games" pulled 50 replays spread across every format a player had touched
  rather than 50 of the selected one. Jack caught this from using the app.
- search.json matches its format parameter as a SUFFIX, so asking for gen9ou also
  returned smogtours-gen9ou - a different format everywhere else in the app.
  Found by testing three top ladder players, not by reading documentation.
- The forfeit flag was battle-level, so a "forfeit" tag beside the opponent's
  name claimed they gave up when it was just as often the player. Caught because
  a sample had 16 forfeits but only 7 losses.
- The public-replay caveat was the else-branch of a loading check, so it vanished
  the moment the statistics it qualifies appeared.
- Type icons fell under Vite's inline threshold and were base64'd into the main
  JS chunk, adding ~14 kB gzip to every page load including pages with no types.
- Full-bleed replay tables spilled past the cards' rounded corners.
- Bootstrap's default muted grey measured 4.40:1 on the new themed background - a
  contrast failure, on text used throughout the app. Caught by computing the
  ratios rather than eyeballing them.

2026-08-15:
- "Most Common Loses" should have read "Losses" - the verb where the noun
  belongs. Jack caught it. Renamed through the aggregation key too, so the code
  and the label agree.
- Rendering the game-count picker a second time would have duplicated its input
  ids and put both copies in one radio group, which makes a label activate the
  wrong control. Each copy now takes an instanceId. Found by reasoning about the
  HTML before shipping it, not from a broken page.
Introduced and fixed the same session:
- The start page forgot its selected format whenever you opened a player and came
  back, always resetting to Gen 9 OU. It was component state, and that page
  unmounts on navigation. Now kept in the URL (so the back link, the browser's
  back button and shared links all work) and mirrored to localStorage (for
  arrivals with no format in the URL). Jack found it by using the app.
- The replay-count column was blank on first load and only populated after
  switching format. Its scheduler's stop() was a one-way latch, and React's
  StrictMode mounts effects twice in development - the single cleanup permanently
  disarmed the only loader the first format would ever get. Jack found it by
  running the app; reading the code had not. stop() is now paired with start(),
  and scripts/check-count-loader.mjs tests that exact mount/cleanup/mount
  sequence along with the concurrency cap and queue priority (11 checks).

Two found while adding the ladder's replay-count column, both pre-existing:
- The Recent Replays list never applied the exact-format filter, so a list
  captioned "Gen 9 OU" could contain smogtours-gen9ou replays - the 2026-08-09
  suffix bug, still live in a second code path. Confirmed against live data the
  same day: one of the top 25 OU players had exactly such an entry on page 1.
- That list attributed replays to players by index into a list with the failures
  already filtered out, which collapses the indices. A single failed request
  would have labelled every replay after it with the wrong player and rank.
Two wrong assumptions in the project's own verification script:
- It assumed six is the maximum team size; gen9randombattlesharedpowerb12p6
  brings twelve.
- It assumed a Pokémon can faint only once; Revival Blessing revives one, and
  gen9purehackmons-2663042252 has 14 faint lines across 8 Pokémon.

METHOD
Behaviour was verified against live Showdown data rather than assumed - each
change was checked by fetching real replays and inspecting the parsed output, and
several of the bugs above were found that way. Colour choices were validated with
WCAG contrast calculations. Four scripts guard regressions:
scripts/validate-parser.mjs, scripts/check-ladder-counts.mjs,
scripts/check-count-loader.mjs and .claude/hooks/guard-paths.test.mjs.
